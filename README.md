# VtM_LoCh_fP

### Vampire: The Masquerade — V20 Character Sheet

**Интерактивный лист персонажа для Vampire: The Masquerade 20th Anniversary Edition (V20).**

VtM_LoCh_fP — настольное Windows-приложение, предназначенное для создания, редактирования и ведения персонажей Vampire: The Masquerade V20.

Приложение объединяет инструменты управления характеристиками, способностями, преимуществами, дисциплинами, игровыми ресурсами, историей и снаряжением персонажа. Автоматические расчёты, учёт игровых расходов, расширенная база данных и генератор персонажей позволяют упростить подготовку к игре.

## Возможности

### Управление персонажами

- Создание нескольких персонажей.
- Переключение между персонажами.
- Индивидуальные файлы сохранения.
- Редактирование основной информации персонажа.
- Создание независимых копий персонажей.
- Импорт и экспорт персонажей.
- Автоматическое сохранение изменений.
- Защита повреждённых файлов сохранений от случайной перезаписи.
- Добавление индивидуальных портретов.
- Хранение изображений непосредственно в файле персонажа.

### Создание персонажей

Предусмотрены два режима создания персонажа:

- **Свободный Неонат** — создание персонажа с использованием стандартной системы распределения характеристик и возможностью гибкой настройки.
- **Птенец на поводке Сира** — создание персонажа по стандартной системе распределения, ограничениям и правилам развития из основной книги.

Помимо ручного создания доступен автоматический генератор персонажей. Он позволяет получить готового персонажа, самостоятельно распределяя характеристики, способности, преимущества и игровые ресурсы.

## Создание персонажей

### Свободный Неонат

Режим предназначен для создания персонажа с использованием стандартных правил V20.

Игрок самостоятельно распределяет первоначальные пункты между характеристиками, способностями, добродетелями, дисциплинами и остальными доступными игровыми параметрами.

При создании учитываются:
- Начальные значения характеристик.
- Приоритеты распределения.
- Доступные пункты.
- Ограничения максимальных значений.
- Стоимость приобретений.
- Правила использования свободных пунктов.

Режим также позволяет гибко настраивать персонажа и использовать дополнительные возможности приложения.

### Птенец на поводке Сира

Режим предназначен для создания персонажа с более строгим соблюдением стандартной системы распределения.

В процессе создания применяются ограничения и правила, предусмотренные выбранной системой создания персонажа.

### Автоматическая генерация

Генератор создаёт персонажа на основе набора именных профилей, игровых правил, базы данных и специальных таблиц генерации.

В отличие от простого случайного распределения характеристик, генератор использует взаимосвязанные параметры: клан определяет приоритеты атрибутов, именной профиль влияет на распределение способностей и биографических фактов, а выбранные Натура и Маска участвуют в формировании истории и внешнего вида персонажа.

Подробная механика описана в следующем разделе.

## Алгоритм генерации персонажей

### Общий принцип работы

Генератор реализован как последовательная система формирования персонажа.

Основная логика находится в `RandomCharacterGenerator.cs`, работа с именными профилями выполняется через `GenerationPatternService.cs`, а генерация текстовых и дополнительных характеристик осуществляется посредством `GenerationStageService.cs`.

Для работы используются:
- Основная игровая база `Data/data.json`.
- Файл профилей `Data/Generation/patterns.json`.
- Файл текстовых шаблонов `Data/Generation/stages_3_7.json`.
- Настройки правил создания персонажа.
- Справочники кланов, дисциплин, фактов биографии, архетипов, достоинств и недостатков.

Генерация выполняется в режиме «Свободный Неонат».

### 1. Выбор именного профиля

В `patterns.json` содержится 20 заранее подготовленных именных профилей.

Каждый профиль содержит:
- Имя персонажа.
- Пол.
- Три приоритета кланов.
- Приоритеты распределения способностей.
- Пять возможных Натур.
- Пять возможных Масок.
- Четыре группы приоритетов фактов биографии, по три варианта в каждой.

Генератор случайным образом выбирает один из двадцати профилей.

Имя и пол определяются выбранным профилем и далее используются при формировании персонажа и его биографии.

### 2. Определение клана

Клан определяется на основании приоритетов выбранного именного профиля.

В текущей реализации используется первый клан из списка приоритетов.

Дополнительно для каждого клана в `patterns.json` предусмотрен собственный порядок распределения атрибутов.

Таким образом, выбор клана непосредственно влияет на дальнейшее формирование характеристик персонажа.

### 3. Определение Натуры и Маски

Натура и Маска выбираются случайным образом из пяти вариантов, предусмотренных выбранным профилем.

Для Маски дополнительно определяется соответствующее амплуа.

Соответствие между Маской и амплуа хранится в отдельной таблице `mask_roles` файла `patterns.json`.

Выбранные значения используются при дальнейшей генерации биографии и внешнего вида персонажа.

### 4. Определение Сира

Для определения Сира используется тот же набор именных профилей.

Генератор формирует список профилей противоположного пола и случайным образом выбирает один из них.

Таким образом, имя Сира также берётся из заранее подготовленной базы именных профилей.

### 5. Определение поколения и начальных параметров

Персонажу устанавливается 13-е поколение.

На основании поколения автоматически определяются:
- Максимальный запас крови.
- Количество крови, расходуемое за ход.
- Максимальные значения характеристик.
- Максимальные значения дисциплин.

Также устанавливается система Человечности.

### 6. Распределение атрибутов

Распределение атрибутов выполняется по трём группам:

- Физические.
- Социальные.
- Ментальные.

Приоритеты групп определяются выбранным кланом.

Для каждой группы используется соответствующий пул пунктов, заданный настройками правил создания персонажа.

Все атрибуты первоначально получают базовое значение, после чего оставшиеся пункты случайным образом распределяются между ними.

При распределении учитываются ограничения максимального значения, установленные правилами создания персонажа.

### 7. Распределение способностей

Способности разделяются на три группы:

- Таланты.
- Навыки.
- Знания.

Приоритеты этих групп определяются именным профилем.

Для каждой группы выделяется собственный пул пунктов.

В отличие от атрибутов, способности первоначально имеют нулевые значения. Затем пункты распределяются случайным образом с учётом максимального значения при создании.

Таким образом, каждый сгенерированный персонаж получает собственное сочетание развитых способностей.

### 8. Распределение добродетелей

Генератор распределяет первоначальные пункты между тремя добродетелями:

- Совесть.
- Самоконтроль.
- Смелость.

Каждая добродетель получает базовое значение, после чего дополнительные пункты распределяются случайным образом.

Максимальное значение ограничивается пятью.

После распределения автоматически рассчитываются:
- Постоянная Сила воли на основании Смелости.
- Первоначальная Человечность на основании суммы Совести и Самоконтроля.

### 9. Выбор фактов биографии

Для выбора фактов биографии используется система приоритетов из именного профиля.

Всего предусмотрено четыре группы приоритетов, каждая из которых содержит три факта.

Сначала генератор формирует общий список доступных фактов и устраняет повторения.

Затем случайным образом определяется количество выбираемых фактов — от одного до пяти.

Выбор выполняется с использованием весовой системы:
- Первая группа имеет вес 4.
- Вторая группа имеет вес 3.
- Третья группа имеет вес 2.
- Четвёртая группа имеет вес 1.

Это означает, что более приоритетные факты имеют большую вероятность выбора, однако менее приоритетные также могут попасть в итоговый набор.

После выбора фактов распределяются пять первоначальных пунктов.

Каждый выбранный факт получает минимум одну точку. Оставшиеся пункты распределяются случайным образом между выбранными фактами.

Максимальное значение отдельного факта ограничивается пятью.

### 10. Выбор дисциплин

На основании выбранного клана определяется список доступных клановых дисциплин.

Из списка случайным образом выбираются до трёх различных дисциплин.

Каждая выбранная дисциплина первоначально получает первый уровень.

При выборе используются данные справочника дисциплин.

### 11. Распределение свободных пунктов

После первоначального распределения характеристик, способностей, добродетелей, фактов биографии и дисциплин генератор переходит к автоматической закупке за свободные пункты.

Начальное количество свободных пунктов определяется настройками создания персонажа.

В стандартной конфигурации используется 15 пунктов.

Распределение состоит из нескольких последовательных этапов.

#### 11.1. Выбор достоинств и недостатков

Сначала генератор случайным образом определяет, будет ли персонаж получать достоинства и недостатки.

Вероятность пропуска этого этапа составляет 50%.

Если этап выполняется, выбирается один из трёх вариантов:
- Только достоинства.
- Только недостатки.
- Достоинства и недостатки одновременно.

Для выбранного направления определяется случайный бюджет от одного до четырёх пунктов.

Затем из базы достоинств и недостатков выбираются подходящие элементы.

При выборе учитываются:
- Стоимость.
- Доступность приобретения.
- Требования к другим элементам.
- Несовместимость отдельных достоинств и недостатков.
- Зависимости между приобретениями.

Если выбранный элемент требует предварительного приобретения другого элемента, генератор пытается выделить для него подходящую часть бюджета.

Если необходимое условие выполнить невозможно, такой вариант исключается.

Недостатки увеличивают доступное количество свободных пунктов, а достоинства расходуют их.

#### 11.2. Обязательное развитие дисциплины

Если после выбора достоинств и недостатков остаётся не менее семи свободных пунктов, генератор выполняет обязательное приобретение дисциплины стоимостью семь пунктов.

Возможны два варианта:
- Повышение уже имеющейся дисциплины.
- Приобретение новой дисциплины первого уровня.

При выборе новой дисциплины исключаются некромантия и тауматургия.

Повышение выполняется с учётом максимального уровня дисциплины.

#### 11.3. Дополнительные пакеты приобретений

После обязательного развития дисциплины оставшиеся свободные пункты распределяются с помощью системы заранее подготовленных пакетов.

Пакеты выбираются случайным образом из соответствующих таблиц в зависимости от доступного бюджета.

Они могут включать:
- Повышение атрибутов.
- Повышение способностей.
- Приобретение новых способностей.
- Повышение фактов биографии.
- Развитие дисциплин.
- Повышение добродетелей.
- Повышение Человечности.
- Повышение Силы воли.

Перед применением пакета генератор проверяет возможность выполнения всех входящих в него приобретений.

Если хотя бы одно приобретение невозможно, пакет не применяется и выполняется повторный выбор.

Это позволяет избежать частичного применения неподходящих пакетов.

#### 11.4. Распределение оставшихся пунктов

Если после применения пакетов остаются свободные пункты, запускается дополнительное распределение.

В первую очередь учитываются:
- Сила воли.
- Человечность.
- Факты биографии.

При этом соблюдаются максимальные значения соответствующих характеристик.

Если подходящих приобретений больше нет, оставшиеся пункты могут быть потеряны.

### 12. Формирование журнала покупок

После распределения всех пунктов генератор формирует историю первоначальных приобретений и покупок за свободные пункты.

Для каждой операции сохраняются:
- Название приобретения.
- Категория.
- Предыдущее значение.
- Новое значение.
- Стоимость.
- Источник приобретения.
- Порядок выполнения.
- Идентификатор партии генерации.

Таким образом, сгенерированный персонаж получает полноценную историю распределения и расходования игровых ресурсов.

### 13. Генерация биографических данных

Для персонажа случайным образом определяются:
- Дата рождения.
- Дата смерти.
- Видимый возраст.
- Рост.
- Вес.

Дата смерти рассчитывается на основании даты рождения и выбранного возраста.

Настоящий возраст первоначально обозначается как неизвестный.

### 14. Генерация предыстории

Для формирования предыстории используется `stages_3_7.json`.

Текст создаётся из отдельных шаблонов и вариантов, которые объединяются в единое описание.

При формировании учитываются:
- Имя персонажа.
- Пол персонажа.
- Натура.
- Профессия.
- Сфера деятельности.
- Имя Сира.
- Выбранные факты биографии.
- Уровни фактов биографии.

Для каждого выбранного факта определяется соответствующий текстовый фрагмент на основании его текущего уровня.

Дополнительно используются специальные шаблоны для отдельных элементов биографии, включая профессию, сферу деятельности и благосостояние.

После выбора фрагменты объединяются в единый текст.

Выполняется подстановка имён, грамматическое согласование рода персонажа и Сира, а также очистка лишних пробелов.

### 15. Генерация отличительных черт внешности

Внешность персонажа формируется посредством последовательного выбора взаимосвязанных параметров.

Используются пять групп данных:

1. Часть тела.
2. Вид особенности.
3. Форма.
4. Болезненность или состояние.
5. Отношение персонажа к особенности.

Сначала выбирается часть тела и соответствующая область.

Затем из доступных вариантов выбирается вид особенности, совместимый с выбранной областью.

После этого определяются подходящая форма и состояние.

Последним выбирается отношение персонажа к особенности.

Для этого этапа используются дополнительные ограничения совместимости. Например, отношение персонажа зависит от выбранного состояния особенности.

Все выбранные элементы объединяются в текстовое описание с использованием шаблонов формулировок.

В итоговом тексте также учитывается пол персонажа.

### 16. Генерация одежды и снаряжения

Одежда формируется из трёх взаимосвязанных компонентов:

- Верхняя часть одежды определяется на основании Маски.
- Нижняя часть одежды определяется на основании Натуры.
- Аксессуары подбираются с учётом клана.

Для каждого компонента используются соответствующие таблицы вариантов.

После выбора элементы объединяются в единое описание одежды.

Количество предметов, находящихся в карманах и при себе, определяется случайным образом с использованием весовой таблицы.

Затем из общего списка предметов выбирается необходимое количество различных элементов.

#### Выбор оружия

Для выбора оружия анализируются три способности:
- Драка.
- Фехтование.
- Стрельба.

Определяется максимальное значение среди этих способностей.

Если максимальное значение имеют несколько способностей, оружие подбирается для каждой из них.

Для Стрельбы дополнительно определяется количество полных перезарядок.

#### Выбор брони

Вероятность получения брони составляет 25%.

В остальных случаях персонаж принципиально не носит броню.

### 17. Завершение генерации

После выполнения всех этапов персонажу устанавливаются первоначальные значения текущей крови и состояния здоровья.

Затем выполняется экспорт сформированного персонажа во временный JSON-файл.

После этого файл импортируется обратно стандартными средствами приложения.

Такая процедура позволяет использовать обычный механизм загрузки персонажа и проверить корректность сериализации сформированных данных.

Временный файл после завершения операции удаляется.

Итоговый персонаж возвращается приложению и добавляется в список персонажей.

### Файлы системы генерации

| Файл | Назначение |
|---|---|
| `RandomCharacterGenerator.cs` | Основной алгоритм генерации, распределение характеристик и закупка за свободные пункты |
| `GenerationPatternService.cs` | Загрузка, проверка и обработка именных профилей |
| `GenerationStageService.cs` | Формирование предыстории, внешности, одежды и снаряжения |
| `Data/Generation/patterns.json` | Именные профили, клановые приоритеты, приоритеты способностей и фактов биографии |
| `Data/Generation/stages_3_7.json` | Текстовые шаблоны и таблицы генерации дополнительных данных |
| `Data/data.json` | Основная база игровых характеристик и способностей |

## Портреты персонажей

Для каждого персонажа можно добавить индивидуальный портрет.

При нажатии на область портрета открывается окно выбора изображения.

Поддерживаются распространённые графические форматы, включая:

- JPG.
- JPEG.
- Другие поддерживаемые графические форматы.

После выбора файла открывается отдельное окно редактирования изображения.

- Перемещение изображения.
- Изменение масштаба.

## Обновление

Приложение поддерживает автоматическую проверку обновлений через GitHub Releases.

При открытии меню персонажей выполняется проверка опубликованной версии.

Если обнаружена новая версия, в меню появляется кнопка **«Обновить»**.

Для обновления:

1. Откройте приложение.
2. Перейдите в меню персонажей.
3. Дождитесь проверки обновлений.
4. Если доступна новая версия, нажмите кнопку «Обновить».
5. Ознакомьтесь с информацией об обновлении и подтвердите установку.
6. Дождитесь завершения процесса.

Также обновление можно выполнить вручную, скачав новую версию из раздела [Releases](https://github.com/taran700/VtM_LoCh_fP/releases).

### Информация для публикации обновлений

Проверка версии использует файл `version.json` из корня основной ветки репозитория.

При выпуске новой версии необходимо обновить этот файл.

Для корректной работы EZ_Updater необходимо соблюдать следующие условия:

- Публиковать обновления в GitHub Releases.
- Использовать тег релиза с номером версии, например `v1.0.6`.
- Прикладывать ZIP-архив приложения.
- Использовать корректную ссылку на архив в `version.json`.

### Структура version.json

- `version` — номер версии, совпадающий с тегом релиза без префикса `v`;
- `assetName` — имя ZIP-архива релиза;
- `downloadUrl` — прямая HTTPS-ссылка на архив в GitHub Releases;
- `releaseName` — название обновления.

Сначала необходимо опубликовать релиз и загрузить ZIP-архив, затем обновить `version.json` в основной ветке.

Автоматическая проверка ограничена одним запросом в 24 часа. Проверка по кнопке выполняется каждый раз и не изменяет таймер автоматической проверки.

Сетевые запросы приложения используют TLS 1.2.

## Хранение данных

Пользовательские данные хранятся отдельно от каталога установки приложения.

### Персонажи

Каталог:

```text
Документы/VtM_LoCh_fP/
```

Каждый персонаж сохраняется в отдельном JSON-файле:

```text
character_<id>.json
```

Файлы персонажей содержат индивидуальные данные соответствующих персонажей:
- Основную информацию.
- Характеристики.
- Способности.
- Дисциплины.
- Преимущества.
- Историю.
- Снаряжение.
- Портрет.

Изображения портретов хранятся непосредственно в JSON в виде Base64.

Это позволяет хранить персонажа и его изображение в одном файле без необходимости использования отдельных графических файлов.

### Совместимость сохранений

При изменении структуры данных приложения сохраняется поддержка предыдущих форматов JSON.

Отсутствующие в старых сохранениях поля обрабатываются без необходимости ручного редактирования файлов.

Например, персонажи, созданные до появления системы портретов, продолжают открываться без ошибок.

### Настройки приложения

Настройки хранятся отдельно в XML-файле:

```text
%AppData%/VtM_LoCh_fP/settings.xml
```

В настройках сохраняются параметры оформления, игровые настройки и информация, связанная с проверкой обновлений.

### Резервное копирование

Рекомендуется периодически создавать резервные копии каталога:

```text
Документы/VtM_LoCh_fP/
```

При необходимости также сохраните:

```text
%AppData%/VtM_LoCh_fP/
```

**Важно:** не изменяйте структуру файлов сохранений вручную и не удаляйте их без необходимости.
