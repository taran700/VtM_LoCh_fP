# VtM_LoCh_fP

### Vampire: The Masquerade — V20 Character Sheet

Интерактивный лист персонажа для **Vampire: The Masquerade 20th Anniversary Edition (V20)**

## О приложении

**VtM_LoCh_fP** — Windows-приложение для создания и ведения персонажей V20. В нём можно хранить несколько персонажей, заполнять их листы, следить за игровыми ресурсами и развивать персонажа по мере игры.

Приложение объединяет лист персонажа, генератор, справочные данные и инструменты развития. Автоматические расчёты и журнал покупок помогают меньше отвлекаться на ручной подсчёт.

> Проект не является официальным продуктом World of Darkness. Названия Vampire: The Masquerade и V20 используются для обозначения совместимости.

## Возможности

### Персонажи и сохранения

Создавайте несколько персонажей и переключайтесь между ними. Для персонажей доступны отдельные сохранения, копирование, импорт и экспорт. Данные сохраняются в JSON, а портрет хранится внутри файла персонажа.

### Создание персонажа

Создавайте персонажа вручную в одном из двух режимов:

- **Свободный Неонат** — гибкая настройка и распределение характеристик.
- **Птенец на поводке Сира** — создание с более строгими ограничениями выбранной системы.

После создания персонаж становится доступен в основном листе: его данные можно дополнять, редактировать и развивать по мере игры.

<img width="1918" height="1015" alt="Создание персонажа" src="https://github.com/user-attachments/assets/b21c60b5-f126-45e0-92d8-252a851f38e6" />

### Генератор персонажа

Генератор помогает быстро получить основу нового персонажа, не распределяя все параметры вручную. Он использует игровые данные **Globulus_Maximus** и выбранный профиль генерации, чтобы сформировать набор характеристик и заполнить основные разделы листа.

В результате генерации подбираются:

- атрибуты и способности;
- дисциплины;
- биографические данные персонажа.

После формирования персонажа создаётся **история покупок** — она отражает распределение пунктов, выполненное в процессе генерации. Полученный результат можно открыть в листе персонажа и продолжить редактировать вручную.

### Лист персонажа и развитие

Лист собирает основные сведения о персонаже в одном месте. В нём доступны атрибуты и способности, дисциплины и ритуалы, преимущества, достоинства и недостатки, биография, заметки и снаряжение.

По мере игры можно развивать характеристики, учитывать опыт и свободные пункты, а также следить за игровыми ресурсами: здоровьем, кровью, Силой воли, Человечностью и Путём.

## Техническая часть

Этот раздел описывает устройство приложения на уровне его основных функциональных подсистем и потоков данных. Он отражает заявленные возможности проекта и не предполагает конкретный архитектурный шаблон (например, MVVM), если он отдельно не подтверждён исходным кодом.

### Алгоритмическая логика

Основная логика приложения связана с созданием персонажа, применением игровых ограничений, генерацией начальных данных и дальнейшим учётом изменений.

#### Создание персонажа

При ручном создании пользователь выбирает режим и заполняет данные персонажа. Режим **«Свободный Неонат»** предоставляет более свободное распределение характеристик, а **«Птенец на поводке Сира»** использует более строгие ограничения выбранной системы. В результате формируется персонаж, с которым можно продолжить работу в основном листе.

#### Генерация персонажа

Генератор формирует начальный вариант персонажа на основе игровых данных и выбранного профиля генерации. В общий процесс входят:

1. Получение доступных игровых данных и параметров выбранного профиля.
2. Подбор характеристик, способностей и дисциплин.
3. Формирование биографических данных персонажа.
4. Подготовка результата для дальнейшего редактирования в листе.
5. Формирование истории покупок, чтобы отразить выполненное распределение пунктов.

Сгенерированный персонаж остаётся доступен для последующего изменения вручную.

##### Activity Diagram алгоритма генерации

Схема отражает последовательность этапов, описанную для `RandomCharacterGenerator.cs`, `GenerationPatternService.cs` и `GenerationStageService.cs`. В ней отдельно показаны проверки бюджета и допустимости приобретений.

<img width="716" height="2414" alt="AD" src="https://github.com/user-attachments/assets/37c44919-e471-487a-8c09-9b79729d3975" />


**Примечания к схеме:**

- Генерация выполняется в режиме «Свободный Неонат».
- Первый клан из списка приоритетов профиля используется как выбранный клан.
- Этап достоинств и недостатков пропускается с вероятностью 50%; если он выполняется, выбирается одно из трёх направлений.
- Пакет дополнительных приобретений применяется только целиком: если хотя бы один пункт пакета недоступен, пакет отклоняется и выбирается другой.
- Если подходящих приобретений больше нет, неиспользованные свободные пункты могут остаться нераспределёнными.
- Шанс получения брони составляет 25%.
- После сериализации во временный JSON персонаж повторно загружается стандартным механизмом приложения; временный файл удаляется.

#### Развитие и игровые ресурсы

При развитии персонажа приложение позволяет учитывать опыт и свободные пункты, а также отслеживать изменения характеристик и игровых ресурсов. Отдельные треки предназначены для показателей здоровья, крови, Силы воли, Человечности и Пути.

Изменение значений треков обрабатывается логикой приложения; для части этой логики в репозитории предусмотрен отдельный тестовый проект. Точные формулы стоимости повышения характеристик и все частные правила V20 здесь намеренно не перечисляются: их корректнее сверять с реализацией и используемыми игровыми данными.

#### Сохранение и загрузка

Данные персонажа сериализуются в JSON и сохраняются в пользовательском каталоге. При повторной работе приложение загружает сохранённые данные, чтобы восстановить состояние листа. Портрет включается в файл персонажа, поэтому он переносится вместе с соответствующим сохранением.

### Архитектура приложения

На уровне функционального устройства приложение можно разделить на несколько взаимосвязанных частей:

| Подсистема | Назначение |
|---|---|
| **Пользовательский интерфейс** | WPF-окна и элементы управления для выбора персонажа, создания, редактирования и просмотра листа. |
| **Логика персонажа** | Обработка характеристик, способностей, дисциплин, преимуществ, развития и игровых треков. |
| **Генератор** | Подготовка персонажа на основе игровых данных и профилей генерации. |
| **Игровые данные** | Справочная информация, используемая листом персонажа и генератором. |
| **Хранение данных** | Чтение и запись персонажей в JSON, а также хранение пользовательских настроек. |
| **Оформление** | Ресурсы и настройки светлой и тёмной тем. |
| **Обновление** | Проверка доступности новых версий через GitHub Releases. |

Упрощённый сценарий взаимодействия выглядит следующим образом:

1. Пользователь выполняет действие в интерфейсе — создаёт персонажа, меняет параметр или открывает сохранение.
2. Приложение обрабатывает действие и обновляет соответствующие данные персонажа.
3. Связанные значения и игровые треки приводятся в актуальное состояние.
4. При сохранении обновлённые данные записываются в файл персонажа.
5. При следующем открытии сохранения данные загружаются обратно в интерфейс.

Это функциональное представление потока данных, а не диаграмма конкретных классов или утверждение об использовании определённого паттерна проектирования.

## Установка

1. Откройте [страницу Releases](https://github.com/taran700/VtM_LoCh_fP/releases).
2. Скачайте установщик или ZIP-архив из раздела **Assets** последнего релиза.
3. Если скачан ZIP, распакуйте его в отдельную папку.
4. Запустите `VtM_LoCh_fP.exe`.

При первом запуске приложение создаёт необходимые каталоги пользовательских данных.

### Системные требования

- Windows 7 или новее.
- .NET Framework 4.8.

Если .NET Framework 4.8 отсутствует, установите его с [официального сайта Microsoft](https://dotnet.microsoft.com/en-us/download/dotnet-framework/net48) или подтвердите его установку, воспользовавшись установщиком.

## Хранение данных

Файлы персонажей находятся в каталоге:

```text
Документы/VtM_LoCh_fP/
```

Настройки приложения хранятся отдельно:

```text
%AppData%/VtM_LoCh_fP/settings.xml
```

**Рекомендуется периодически делать резервную копию** каталога `Документы/VtM_LoCh_fP/`. При необходимости сохраните также `%AppData%/VtM_LoCh_fP/`.

## Сборка из исходного кода

### Требования

- Visual Studio 2022 или совместимая версия с компонентами разработки классических приложений .NET.
- .NET Framework 4.8 Developer Pack / Targeting Pack.
- Для тестового проекта — .NET 9 SDK.

### Сборка

```bash
git clone https://github.com/taran700/VtM_LoCh_fP.git
```

Откройте `VtM_LoCh_fP.sln` в Visual Studio, выберите конфигурацию `Release` и платформу `Any CPU`, затем выполните **Build → Build Solution**.

Исполняемый файл после сборки:

```text
VtM_LoCh_fP/bin/Release/VtM_LoCh_fP.exe
```

## Тесты

В репозитории есть отдельный тестовый проект для логики игровых треков.

```bash
dotnet run --project tests/DotTrackLogic.Tests.csproj
```

Успешное выполнение выводит:

```text
All TrackLogic checks passed.
```

Тесты не заменяют полноценную проверку интерфейса и сборки WPF-приложения.
